## 1. 전략적 배경 및 목적

### 🔴 배경
- 2030 독서 인구는 "독서모임은 부담스럽고, 혼자 읽기는 지속이 안 되는" 중간 지대에 넓게 분포함. 독서모임은 시간·장소·발언 부담, 혼자 읽기는 동기 부족으로 이탈.
- 기존 서비스의 공백:
  - **밀리의서재**: 콘텐츠·개인 챌린지 중심. 유저 간 대결·실시간 동행 없음.
  - **북이오 등 실시간 함께읽기**: 같은 시간 접속을 강제 → 2030의 불규칙한 생활 패턴과 충돌.
  - **리더스 등 기록 SNS**: 완독 후 피드 공유에 그쳐 '읽는 도중'의 몰입감이 약함.
- 콘텐츠 라이선싱은 스타트업이 넘기 힘든 진입장벽. Goodreads처럼 **콘텐츠 없이 관계만 소유**하는 모델이 초기 단계에 적합.

### 🟢 비즈니스 목적
- **'읽는 도중'의 소셜 레이어 카테고리 선점:** 완독 후 기록이 아니라 읽는 도중의 동행·경쟁을 핵심 가치로 포지셔닝.
- **네트워크 효과 기반 성장:** 1명이 방을 만들면 평균 2~4명이 초대 링크로 유입되는 구조 → 유료 마케팅 없는 초기 성장 검증.
- **제휴 협상 자산 확보:** 활성 독서 그룹 데이터를 근거로 출판사·이북 플랫폼과 본문 제휴(Phase 3) 협상.

### 🧭 제품 원칙
1. **본문은 합법 소스만.** 퍼블릭 도메인 외 본문은 저장·배포하지 않는다.
2. **비동기가 기본, 동기는 보너스.** 시간을 맞추지 않아도 함께 읽는 느낌이 나야 한다.
3. **스포일러는 버그다.** 내가 아직 안 읽은 위치의 반응은 기본적으로 가린다.
4. **경쟁은 팀 단위로.** 개인 순위는 스트레스, 팀 순위는 소속감.

## 2. 사용자 페르소나 (상세)

### 👤 페르소나 A — 방장 (독서모임이 부담스러운 대학생)

> **김서연, 22세, 여성, 국문과 3학년**
> 교양 수업에서 김유정·이상의 단편을 읽어야 하는데 혼자 읽으면 자꾸 미룬다. 과 동기 3명과 "이번 주 안에 「봄봄」 다 읽기"를 하고 싶지만, 시간을 맞춰 모이는 독서모임은 조별과제만큼 부담스럽다. 인스타 스토리·카톡으로 링크를 공유하는 데 익숙하고, 누가 어디까지 읽었는지 보이면 자극을 받는 편.
> **핵심 니즈:** 링크 한 번으로 친구를 부르는 가벼운 시작, 친구가 어디까지 읽었는지 실시간으로 보이는 긴장감, 과제용 인상 깊은 구절을 모아 두는 기능.

### 👤 페르소나 B — 참여자 (퇴근 후 틈틈이 읽는 직장인)

> **박준호, 29세, 남성, IT 회사 3년차**
> 출퇴근 지하철과 자기 전 20분이 독서 시간의 전부. 친구들과 같은 책을 읽기로 해도 늘 페이스가 달라 대화가 어긋난다. 친구가 먼저 읽고 남긴 반응이 궁금하지만, 결말 스포일러는 절대 싫다. 리디에서 산 상용 전자책도 같이 기록하고 싶어한다.
> **핵심 니즈:** 내 속도대로 읽어도 소외되지 않는 비동기 경험, 내 위치까지만 보이는 반응(스포일러 가드), 상용 도서의 진행률 수동 기록.

### 👤 페르소나 C — 경쟁 선호자 (게임화에 반응하는 대학원생)

> **이도윤, 26세, 논바이너리, 공학 대학원생**
> 듀오링고 리그에서 다이아몬드를 유지하는 사람. 목표·점수·순위가 있어야 움직인다. 연구실 동료들과 팀을 짜서 다른 연구실과 "한 달 고전 완독 레이스"를 해 보고 싶다. 반면 '넘기기만 해서 1등하는' 사람이 있으면 바로 흥미를 잃는다.
> **핵심 니즈:** 공정한 레이스(치팅 방지), 팀 대항전·주간 리더보드, 승리 포인트의 가시적 보상.

### 👤 페르소나 D — 초대받은 사람 (서비스를 처음 접하는 친구)

> **최민지, 23세, 여성, 페르소나 A의 과 동기**
> 서연이 카톡으로 보낸 초대 링크를 눌렀다. 앱 설치도, 긴 가입도 하고 싶지 않다. 30초 안에 "뭘 하는 건지" 이해되지 않으면 창을 닫는다.
> **핵심 니즈:** 링크 → 소셜 로그인 1탭 → 바로 방 입장, 가입 전에도 방 정보(책·멤버·진행률) 미리보기.

## 3. 사용자 스토리 (User Stories)

> **Story 1 (방장 · 김서연)**
> As a 과제로 같은 책을 읽어야 하는 대학생인 내가, I want to 책을 검색해 읽기방을 만들고 초대 링크를 카톡으로 공유하고 싶다. So that 모임 시간을 잡지 않고도 친구들과 같은 목표를 향해 읽을 수 있기 때문이다.

> **Story 2 (참여자 · 박준호)**
> As a 틈틈이 읽는 직장인인 내가, I want to 친구가 먼저 남긴 반응을 내가 읽은 위치까지만 문단 옆에서 보고 싶다. So that 페이스가 달라도 함께 읽는 느낌을 받으면서 스포일러는 피하고 싶기 때문이다.

> **Story 3 (참여자 · 박준호)**
> As a 상용 전자책을 가진 내가, I want to 카카오 도서 검색으로 책을 등록하고 진행률(%)을 직접 기록하고 싶다. So that 앱에 본문이 없는 책도 친구들과 진행 상황을 공유할 수 있기 때문이다.

> **Story 4 (경쟁 선호자 · 이도윤)**
> As a 팀 대항전을 원하는 내가, I want to 팀을 만들어 다른 팀과 기간 한정 페이지 레이스를 하고 싶다. So that 개인 부담 없이 소속감과 경쟁심으로 완독까지 가고 싶기 때문이다.

> **Story 5 (경쟁 선호자 · 이도윤)**
> As a 공정한 경쟁을 원하는 내가, I want to 넘기기만 한 구간은 레이스 점수에 반영되지 않기를 원한다. So that 실제로 읽은 사람이 이기는 게임이어야 하기 때문이다.

> **Story 6 (초대받은 사람 · 최민지)**
> As a 초대 링크를 받은 내가, I want to 가입 전에 방 정보를 보고 소셜 로그인 한 번으로 입장하고 싶다. So that 무엇인지 모르는 서비스에 긴 가입 절차를 거치고 싶지 않기 때문이다.

> **Story 7 (방장 · 김서연)**
> As a 인상 깊은 구절을 모으고 싶은 내가, I want to 문장에 밑줄을 긋고 한줄평을 달아 친구들의 투표를 받고 싶다. So that 과제에 쓸 좋은 해석을 함께 고르고 싶기 때문이다.

### BOOK-01 · 통합 도서 검색

`우선순위: P0` · `Phase 1`

**기능 설명**
- 하나의 검색창에서 여러 소스를 병렬 조회(`httpx.AsyncClient` + `asyncio.gather`)해 통합 결과를 반환.
- 소스 어댑터: `kakao`(국내 메타데이터, 1순위), `naver`(국내 보조), `google_books`(해외 메타데이터), `gutendex`(영문 퍼블릭 도메인 전문), `wikisource`(한국 근대문학 퍼블릭 도메인 전문).
- 결과 병합 규칙: ISBN-13 일치 시 1건으로 병합하고 출처 목록을 누적. 전문 제공 가능 소스가 있으면 `has_fulltext=true`.
- 한 소스가 실패하거나 타임아웃(3초)되어도 나머지 결과는 반환(부분 실패 허용). 실패 소스는 응답 `errors` 필드에 기록.
- API 키가 설정되지 않은 소스는 자동 비활성화(개발 환경에서 키 없이도 Gutendex·위키문헌만으로 동작).

**UI/UX**
- 결과 카드에 `전문 읽기 가능`(Action Blue 배지) / `진행률 기록`(회색 배지)을 구분 표기해 두 모드를 사용자가 즉시 인지.
- 표지가 없는 퍼블릭 도메인 도서는 제목 타이포그래피 기반의 기본 표지 생성.

**수용 기준 (AC)**
- [ ] `GET /api/v1/books/search?q=봄봄` → 위키문헌 결과 1건 이상 포함.
- [ ] 소스 1개가 500 에러를 반환해도 200 응답 + `errors`에 해당 소스 기록.
- [ ] 같은 ISBN의 카카오·네이버 결과는 1건으로 병합.

### BOOK-02 · 퍼블릭 도메인 전문 수집·청크화

`우선순위: P0` · `Phase 1`

**기능 설명**
- 전문 소스(Gutendex 텍스트 파일, 위키문헌 `action=parse` HTML)에서 본문을 가져와 정제(HTML 태그·각주·편집 링크 제거) 후 **청크**로 분할해 저장.
- 청크 규칙: 문단 경계를 존중하며 목표 약 1,200자(한글)/약 1,800자(영문) 단위. 각 청크는 `chunk_index`와 문단 앵커 목록을 가진다.
- 청크는 "페이지"를 대체하는 전 시스템 공통 위치 단위 — 진행률·반응·레이스 점수가 모두 청크 인덱스를 기준으로 계산.
- 최초 조회 시 lazy 수집 후 DB 캐시. 동일 도서 재요청 시 외부 API 재호출 없음.

**수용 기준 (AC)**
- [ ] 동일 입력 텍스트에 대해 청크 분할 결과가 항상 동일(결정적).
- [ ] 어떤 청크도 문단 중간에서 잘리지 않음(단, 단일 문단이 한도의 2배를 넘으면 문장 경계에서 분할).

### AUTH-01 · 소셜 로그인

`우선순위: P0` · `Phase 2`

**기능 설명**
- 카카오 / 구글 / 네이버 OAuth 2.0(Authlib). 이메일·비밀번호 가입은 MVP에서 제외.
- 초대 링크(`/r/{invite_code}`)로 진입한 비로그인 사용자는 방 미리보기 → 로그인 → 해당 방으로 자동 복귀(state 파라미터에 복귀 경로 저장).
- 세션: HttpOnly Secure 쿠키 + 서버측 JWT 검증(Access 15분 / Refresh 14일, 회전).

**UI/UX**

## 5. 비기능적 요구사항 및 제약조건

### ⚡ 성능 및 가용성
- **검색 응답:** 통합 검색 P95 1.5초 이하(소스별 타임아웃 3초, 부분 결과 우선 반환).
- **실시간 지연:** 진행률 이벤트 발생 → 방 멤버 화면 반영 P95 1초 이하.
- **리더 로딩:** 청크 1개 응답 P95 200ms 이하(DB 캐시 기준).
- **가용성:** MVP 목표 99.5%(월). 외부 도서 API 장애는 서비스 장애로 전파되지 않음(캐시·부분 실패 허용).

### 🔒 보안 및 컴플라이언스
- **저작권:** 퍼블릭 도메인이 아닌 본문은 저장하지 않음. 도서 레코드의 `has_fulltext`는 화이트리스트 소스(gutendex, wikisource)에서만 true가 될 수 있도록 코드 수준에서 강제.
- **API 약관:** 카카오·네이버 검색 결과는 원 출처 링크를 함께 표시. 알라딘 API는 사업자 전환 시 약관 재검토 전까지 비활성.
- **개인정보:** 수집 최소화(닉네임, 이메일, OAuth 식별자). 탈퇴 시 30일 유예 후 개인정보 파기, 반응·한줄평은 "탈퇴한 사용자"로 익명화.
- **비밀 관리:** 모든 API 키는 환경변수(`.env`, 저장소 커밋 금지), 운영은 시크릿 매니저.
- **치팅 방지 서버 신뢰:** 체류시간 판정은 서버에서 이벤트 타임스탬프 간격으로 재계산 — 클라이언트가 보낸 `dwell_ms`는 상한 검증에만 사용.

### ♿ 접근성
- WCAG 2.1 AA 대비율, 터치 타깃 44×44px 이상, 리더 글꼴 크기 4단계.

## 6. 예외 처리 및 에지 케이스

> **EXC-01. 외부 도서 API 장애 / 쿼터 초과**
> 해당 소스만 결과에서 제외하고 `errors`에 표기. 카카오 쿼터 소진 시 네이버로 자동 폴백. 검색 결과는 10분 캐시.

> **EXC-02. 방 멤버들이 서로 다른 판본을 읽는 경우**
> 방은 하나의 `book_id`에 고정. 트래커 모드 멤버는 % 기준으로만 비교되며 문단 반응은 10% 구간에 귀속.

> **EXC-03. 앞선 사람의 반응이 스포일러가 되는 경우**
> 스포일러 가드 기본 ON. 가드 해제는 방 설정이 아닌 개인 설정(내가 스포일러를 원할 때만).

> **EXC-04. 레이스 도중 탭을 켜두고 방치해 체류시간을 부풀리는 경우**
> 청크당 인정 체류시간 상한 = 최소 체류시간 × 10. 페이지 비가시(visibilitychange) 상태 시간은 제외.

> **EXC-05. WebSocket 연결이 끊긴 경우**
> 클라이언트 지수 백오프 재연결(1s → 30s), 재연결 후 `last_event_id` 이후 이벤트 수신. 오프라인 중 읽기 이벤트는 로컬 큐 후 일괄 전송(서버는 이벤트 시각 기준으로 판정, 24시간 초과 이벤트는 레이스 점수 제외).

> **EXC-06. 방장이 탈퇴하는 경우**
> 가장 먼저 참여한 멤버에게 방장 자동 위임. 멤버가 없으면 방 보관 처리.

> **EXC-07. 위키문헌 문서가 목차(하위 문서 링크)만 있는 경우**
> 하위 문서를 순서대로 수집해 하나의 도서로 병합(최대 200개 하위 문서).
